Ingeniería del Modelo Analítico

Calcular la frecuencia real en entornos corporativos exige superar sesgos estadísticos graves. Los 6 retos resueltos con Tableau LOD Expressions.

01 · Agregación

La "Falsa" Frecuencia Promedio

Conflicto: Promedios simples de facturas generaban agregaciones globales distorsionadas, sin reflejar el comportamiento individual de cada cliente.

Resolución: LOD FIXED para etiquetar cada cliente con su volumen exacto de facturas únicas antes de promediarlo pobalcionalmente.

{ FIXED [Email Cliente] : COUNTD([Numero Factura]) }
02 · Gobierno de Datos

El Identificador Único Absoluto

Conflicto: Una orden con múltiples líneas de producto inflaba artificialmente el conteo de facturas.

[Email Cliente] +
LEFT(STR([Numero Pedido]), LEN(STR([Numero Pedido])) - 2) +
STR([Fecha Pedido])
03 · Flexibilidad Analítica

Ecosistema Temporal Dinámico

Conflicto: La Dirección requería analizar la frecuencia por Año, Semestre y Trimestre desde un único panel.

CASE [Elegir Periodo]
  WHEN "Año"      THEN STR(YEAR([Fecha]))
  WHEN "Semestre" THEN STR(YEAR([Fecha])) + IF MONTH([Fecha])<=6 THEN " S1" ELSE " S2" END
  WHEN "Trimestre"THEN STR(YEAR([Fecha])) + "-Q" + STR(DATEPART('quarter',[Fecha]))
END

{ FIXED [Email Cliente] : COUNTD([ID_Factura_Unico]) } /
{ FIXED [Email Cliente] : COUNTD([Periodo Dinamico]) }
04 · Medición de Intervalos

Ritmo de Compra (Inter-purchase Time)

Conflicto: División por cero en clientes con solo una compra. Necesitábamos medir el "espacio" entre visitas, no las visitas.

DATEDIFF('day',
  {FIXED [Email Cliente]: MIN([Fecha])},
  {FIXED [Email Cliente]: MAX([Fecha])}
) / ({FIXED [Email Cliente]: COUNTD([ID_Factura_Unico])} - 1)
05 · Sesgo Estadístico

El Defecto de los Racimos (Clustering)

Conflicto: 5 tickets el mismo día hacían que el ritmo pareciera muy frecuente cuando el cliente visitaba la tienda solo 1 vez cada 3 meses.

// Ritmo Real: días únicos de visita, no tickets
DATEDIFF('day', MIN([Fecha]), MAX([Fecha])) / (COUNTD([Fecha]) - 1)
06 · Control de Daños

Depuración de Outliers Institucionales

Conflicto: Cuentas corporativas con +14,000 registros distorsionaban los promedios de clientes reales.

Resolución: Filtros de Contexto (Add to Context) para garantizar que los FIXED se evalúen después del filtrado, protegiendo la validez estadística del análisis.

Impacto: La precisión predictiva del modelo de retención aumentó significativamente al operar sobre la distribución de clientes real, no contaminada por outliers institucionales.
