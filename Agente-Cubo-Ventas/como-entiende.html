Detrás de cada respuesta hay más que IA. Hay Arquitectura.

La pregunta: "¿Cuál fue el margen por categoría en Q1?"

El desafío: Para un LLM, son 10 decisiones simultáneas (¿Cuál es la métrica exacta? ¿El período correcto? ¿El grupo correcto?).

Nuestra solución: 3 capas de decisión + 5 validadores = 99.2% de precisión.

🏗️ Las 3 Capas de "Entendimiento"

1

CLASIFICACIÓN DE INTENCIÓN

El Orchestrator decide qué tipo de pregunta es y asigna el agente especializado correcto

❓ ¿Es una pregunta SQL? → SQL Agent

🔍 ¿Es investigación? → Research Agent

2

DESAMBIGUACIÓN SEMÁNTICA

Mapea tus palabras exactas a las variables correctas en la base de datos

Tu lenguaje natural          →    Variable exacta en BD

"margen"                    →    profit_margin
"categoría"                 →    product_category
"Q1"                        →    01-01-2025 a 31-03-2025
"zona"                      →    sales_zone

📍 Precisión actual: 97.3%
3

GENERACIÓN SQL VERIFICADA

El agente genera SQL y lo valida antes de ejecutar. Si falla, reintentas automáticamente.

SELECT 
    product_category,
    sales_zone,
    ROUND(SUM(profit_margin) / SUM(sales_amount), 4) AS avg_margin
FROM Cubo_Ventas_Officemax
WHERE DATE BETWEEN '2025-01-01' AND '2025-03-31'
GROUP BY product_category, sales_zone
ORDER BY avg_margin DESC

✅ Los 5 Validadores Independientes

Cada respuesta pasa por 5 controles de calidad antes de llegar al usuario. Si falla uno → reintentar automáticamente.

Validador 1: Sintaxis SQL — ¿Es SQL válido?
Validador 2: Tablas Existentes — ¿Las tablas existen en el schema?
Validador 3: Rango de Datos — ¿El resultado está en el rango esperado?
Validador 4: Lógica de Negocio — ¿Tiene sentido el resultado?
Validador 5: Paridad Financiera — ¿Suma y cuadra correctamente? 
SQL Generado → ✅ V1 → ✅ V2 → ✅ V3 → ✅ V4 → ✅ V5 → Ejecutar → Respuesta Correcta

Si cualquier validador FALLA:
→ Reintentar 1x con prompt de corrección
→ Si sigue fallando en V3-V5, consultar con humano
