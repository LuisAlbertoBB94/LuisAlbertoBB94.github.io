01. Infraestructura Elástica & FinOps

Diseño de una arquitectura de cómputo efímero para optimización de presupuestos de nube.

El Desafío Cloud

Mantener un cluster de procesamiento encendido 24/7 para un pipeline que solo corre en intervalos específicos es una ineficiencia financiera crítica. En este proyecto, el objetivo era garantizar recursos de alto rendimiento (Spark) sin disparar los costos de Google Cloud.

La Estrategia: Clusters Transientes

Implementamos la configuración de **TTL (Time To Live)** e **Idle Deletion**. El cluster se crea dinámicamente, procesa la carga y se destruye automáticamente tras 60 minutos de inactividad o al finalizar el DAG.

*Tecnologías: Google Cloud Dataproc, e2-standard-4 instances.*

Configuración de Infraestructura (JSON)

Esta es la definición del cluster que Airflow inyecta en la API de GCP para levantar la infraestructura bajo demanda.


{
    "cluster_name": "pipeline-cluster-dynamic",
    "config": {
        "master_config": {
            "num_instances": 1,
            "machine_type_uri": "e2-standard-4",
            "disk_config": { "boot_disk_size_gb": 100 }
        },
        "worker_config": {
            "num_instances": 2,
            "machine_type_uri": "e2-standard-4"
        },
        "lifecycle_config": {
            "idle_delete_ttl": "3600s", // Autodestrucción tras 1 hora de ocio
            "auto_delete_ttl": "7200s"  // Límite máximo de vida de 2 horas
        }
    }
}

Impacto de Negocio

Gracias a la infraestructura efímera, logramos una **reducción del 40% en la facturación mensual** de Dataproc, manteniendo la capacidad de procesar millones de registros en minutos cuando el negocio lo requiere.
